# 企业访谈 AI 系统

独立于 `../yuhuan-design-guide-v9` 的本机系统。已实现首版界面、MCP数据接入、DeepSeek思考模式工具循环和独立百炼语音接口。已完成用户百炼账号下的真实模型、项目库和测试音频联调，记录见 `review/联调记录.md`。

## 通用企业创新关联

系统以不同企业的需求为起点，不预置某个产品或行业答案，也不把同类项目关键词命中作为输出建议的前提。

流程为：企业场景与未知条件 → 功能、约束与矛盾抽象 → 全库候选发现 → 来源核验 → 可迁移概念、合作方式与验证步骤。

首次分页读取网站全部项目和方法题录，缓存24小时；当前真实读取560个项目、64个方法。模型可以从全库题录提出跨行业候选，不把题录浏览说成读完正文。题录仅用于发现候选，项目的技术机制必须以实际档案记录为依据。`map_need`会展示需求、待确认条件、功能与迁移假设；系统自动读取少量动态选出的候选项目概览、现有记录和方法边界，再让模型继续核对、取舍。项目ID与方法ID校验来自真实目录。

建议分清三个层级：来源项目事实、针对本企业的迁移设想、待验证条件。不满足尺度、材料、成本、使用或安全约束的关联应降为弱参考或舍弃。没有可靠库内项目也应给通用方法、概念路线、待补信息和最小验证路径，但不能声称存在已验证技术或承诺落地。

每轮记录并在执行轨迹展示：请求模型、服务商返回模型、实际收到的思考字符数、服务商思考Tokens、用量、耗时和请求编号。未返回思考用量时显示“服务商未返回”，不估算或伪造。思考原文不作为面向企业的长篇展示，展示的是分析摘要和调用凭据。速度本身不能证明是否开启思考。

临时503/限流及网络故障在输出流开始前最多重试两次，失败轮的用户信息仍保留，避免下一轮忘记已确认的企业或产品背景。会话仍为本机内存，重启后需开始新访谈。

## 启动

双击 `启动企业访谈.bat`，浏览器访问 http://127.0.0.1:5188 。需要 Node.js 22 或以上，WebSocket依赖已本地附带，不需要安装依赖。

在「连接设置」填写百炼 API Key、地域及业务空间，DeepSeek与语音共用该账号配置，不再连接DeepSeek官方API。分析模型使用用户指定的 `deepseek-v4.1-flash-1017`，通过百炼兼容接口调用，显式设置 `enable_thinking: true`。语音输入与输出统一使用用户确认控制台可用的 `qwen-audio-3.1-realtime-flash`。该确切ID已通过用户账号真实验证，识别会话与音频输出可用。音色保留可编辑，留空使用上游模型默认音色。

配置仅由本机服务读取，保存在 `.local/config.json`，不嵌入网页、不经配置读取接口返回。交付或复制源码时必须排除 `.local/`。服务仅监听127.0.0.1，检查Host及修改请求Origin。

语音识别文本进入输入框，由操作人确认后发送。输入通道仅向浏览器转发转写文字，模型自动生成的回答不播放；DeepSeek继续负责分析。语音输出只接受服务端最终答复ID，读取对应原文，不能由浏览器任意传文；小D固定开场单独登记。上游生成音频后，先缓存整段音频，将配套语音转写和原文做Unicode规格化及去空白比较；数字、标点与内容必须一致，才返回WAV播放。缺少转写、内容改写、生成不完整均拒绝播放，保留文字结果。核对的是服务商配套转写，不是对音频做第二次独立识别；真实音频还需听测。该检查增加首播等待时间，最长等待120秒，不截断原文，也不自动切回旧TTS。自动播报可选。会话保存在服务端内存，重启丢失；当前最多保留10场访谈，未实现持久化报告保存或导出。

右侧展示模型提供的分析摘要、实际工具参数、查询返回资料及耗时。没有预设假查询或假进度。原小D形象来自原项目图集，当前仅有轻微待机浮动，尚未制作新的动作和口型动画。

## 已确认的产品选择

- 网站项目库和方法库为主，不合并原小D的本地实验室知识库。
- 同时支持文字与语音，沿用小D形象；动画可另做，声音使用百炼。
- 本机运行；DeepSeek通过阿里云百炼负责分析，百炼Qwen Audio Realtime负责企业发言转写与受控播报。
- 意见包含：匹配项目、为什么匹配、怎么合作、实施步骤。

## 验证

通用关联的五行业真实验收见 `review/通用企业关联验收.md`：制造、零售、餐饮、冷链物流、养老服务均完成动态联想与资料核验，不以同类关键词命中作为前提。餐饮初次超时，修正后单独复测通过；本轮浏览器控制不可用，视觉交互未重验。

`npm test`：16项检查通过，覆盖目录候选范围、失败轮上下文、MCP与模型重试、密钥保护、思考用量、语音一致性拦截及本机访问限制。

浏览器检查：首页布局、小D形象与连接设置可正常显示。真实MCP已验证：工具列表、能力说明、项目题录及项目概览；目录返回总数560条。用户账号真实联调通过：完整意见约23秒、14次工具调用，完整语音生成约30秒且配套转写核对通过；合成测试音频经本机桥接识别成功。现场麦克风与回声环境尚待人工测试，音色可稍后试听决定。

## 用户已明确的需求

- 企业介绍自身业务与需求 → AI 检索项目库，判断可提供帮助的项目 → 向企业生成意见。
- 系统独立运行，但仍由小D介绍。
- 界面整体采用酷炫、赛博朋克风格。
- 可视化呈现系统工作：真实调用、查询、执行状态、证据与分析摘要。
- 未明确的业务与产品决策需要询问用户，不自行编造项目、能力或业务规则。

## 数据源核查（2026-10-27）

- 用户指定文档：https://opendesign.cc/inno/mcp/
- 该页面实际读取成功（HTTP 200）。它是好设计的项目与创新方法库接入说明，不是网站根路径 `/mcp/` 下的网页设计参考库。
- 远程 MCP 入口：https://opendesign.cc/inno/mcp/api
- 对该入口发起无密钥 `tools/list` 请求，实际返回 HTTP 401，错误 `access_key_required`，要求 `Authorization: Bearer <your access key>`。
- 用户提供授权配置后，工具列表和能力说明请求均返回HTTP 200。真实题录读取成功；项目2025-00概览返回research-000001版本、102条记录、172项来源，并标明未经专家审核。尚未逐一验证方法正文与引用证据工具，不能把全部目录项目都称作已完成研究或验证的项目。
- 密钥由网站管理员单独提供；网页登录密码不能代替 MCP 访问密钥。

文档列出的八个只读工具：

1. `inno_capabilities`
2. `inno_search_projects`
3. `inno_search_methods`
4. `inno_read_project`
5. `inno_read_method`
6. `inno_search_fields`
7. `inno_read_evidence`
8. `inno_prepare_research`

文档说明：远程服务提供知识与研究包，不调用收费模型，不保存访谈或研究历史；分析生成和需要保留的记录由客户端系统负责。研究包请求一次最多 3 个项目、5 个方法、5 个关键词，返回上限 120KB。项目研究整理版不等于专家审核或工程验证，相关专利不等于项目已采用。
